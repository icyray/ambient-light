C 的问题在于"方向性"：发光是加法（叠亮色），投影是减法（压暗）。
在深色主题下，投影几乎不可见 → 底部那点"灯亮着"的信息就丢了，只剩一条 4px 彩线。

所以选 C 意味着：两套主题各要一套不同的层次语言 —— 浅色用投影（实体卡），深色用辉光（发光体）。 这不再是"一个设计、两种底色"，而是两个设计，也正是方案文档里把它标成"视觉语言重做"的原因。

它换来的是什么：浅色主题下 banner 与下面的卡片形成"悬浮卡片 + 彩色识别带"的干净层次， 不再有"浅底上叠一层彩色"的浑浊感；模式色从"大面积氛围"变成"一条识别线"。

如果哪天要做 C，得动什么

  • 删：GlowBellAlphas 钟形 alpha、ModeGlowColor 的 4 个基色、 GlowBand 的 BlurEffect 与遮罩 → 底部辉光那套 （UpdateGlow / AnimateGlow / 呼吸相位）整体退役；
  • 加：banner 的 DropShadowEffect（或外圈 Border + 阴影）+ 底部内阴影 + 一条模式色底带（模式切换时动画的对象从"辉光颜色/透明度"变成"底带颜色"）；
  • 两套主题各调一遍：浅色 = 投影语言；深色 = 需要另想（例如"深色下用一条更亮的底带 + 微弱内高光"）；
  • 探针要换规则：从"光带/辉光的 |ΔL| 可见性"换成"投影/底带的存在性与对比度"；
  • 顺带：ConfigStore.App.BannerGlow（用户可见的"底边辉光"开关）的语义要重新定义 —— 它在 C 里对应的是"底带/投影"而不是辉光。
